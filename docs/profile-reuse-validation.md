### 停机、数据和启动边界

退出前原 Code 列表中 4 个会话均为 Idle，当前输入为空，Cowork 无运行中任务。01:50:20–01:50:23 原程序日志记录完整正常退出与 40 项清理完成，待发送输入队列为零；该退出并非本轮 agent 发出退出命令，不能归因为 agent 的菜单操作。所有相关应用/worker/终端均退出后才制作快照。独立 CoworkVMService 是系统服务，未停止；其他通用 Node/Python/shell 按路径和父子关系判断，没有因 unknown 标签批量终止进程。

复用 `lib/profile-snapshot.mjs` 得到 323 文件、9,368,361 字节、117 目录的一致停机快照，保留 SQLite sidecar/LevelDB 文件；约 10.91 GB 大组件、缓存、锁和 worker 凭据按既有策略排除。Code 正文不在该 profile 中：另从原 CLI 历史目录按 CLI 会话 ID 选择复制 21 个主历史/子 agent 伴随文件，保留字节及哈希，共可解析 5,202 条 JSONL 记录。原始快照保持不变，在第二候选上调整设置和路径。

候选使用独立 LOCALAPPDATA、APPDATA、USERPROFILE/HOME、CLAUDE_CONFIG_DIR、TEMP/TMP 和工作目录；原数据没有用作启动目录。仅在候选禁用计划/恢复、远程连接、配置的 MCP/扩展入口，清空恢复队列并将工作区操作路径重定向到本轮空目录；网关替换为不可用占位地址。通过 CLI 运行真实副本，没有修改 ASAR 来绕过能力检查，没有改变系统权限或保护。

第一次真实启动出现 `Failed to get 'appData' path`，修复是在隔离 USERPROFILE 内补齐标准 `AppData/Roaming` 与 `AppData/Local` 目录，保留原用户目录隔离；第二次正常启动成功。该故障不同于历史低完整性 `0x80000003`。

启动和导航的实际边界也有局限：原生历史页面会自动创建 4 个隔离工作目录中的待机 PowerShell PTY；日志对模型会话预热记录 `workspace no longer trusted`，没有观察到原 Code 模型 worker 启动，也未提交模型消息。不能宣称“没有子进程执行”。候选的空计划文件一度写成 `{}`，日志出现 `scheduledTasks` 数组缺失校验错误；应以正确结构或移除候选计划文件准备下一次实验，不能将该错误视作正式隔离机制。另有 Documents 原生路径查询回退至真实用户 Documents 的日志，相关迁移记录为 `skipped_root_absent`；本轮原 profile 完整性不覆盖所有系统路径，下一次需预建隔离标准用户目录并核对已知文件夹重定向。

### Cowork 的具体阻塞与最小后续条件

当前应用 ASAR 的 `index.chunk-lzaSYO3Q.js` 中 `oEr()` 对普通 Windows 副本返回 `unsupportedCode: 'msix_required'`，提示 Cowork 要求现代安装器；本轮实际入口灰色、不能切换。复制 VM 大文件不能解决安装身份检查。完成中文 Cowork 列表/历史 UI 验收需要具备合法 MSIX 身份的独立 Windows 测试环境和独立数据，或官方提供支持的只读历史入口；当前没有发现后者。本轮没有伪造 WindowsApps 路径、打开 E2E 能力覆盖或修改系统权限。Code 通过不能扩大为 Cowork 通过，也未验证任务续用、数据库引擎完整性或实时共写 profile。

## 结论

设置与会话数据可以复制到独立目录，并保留记录结构；还没有证明应用副本能完整显示、继续这些会话。此次没有让两个程序并发写同一个日常数据目录，不能声称实时共用数据已安全。

普通权限启动完整快照可能自动恢复 Code/远程连接任务，并尝试注册 claude 协议。为保护现有环境，没有这样启动。仅进行了低完整性、离线网关、移除计划/自动恢复标记的受限启动；应用很快以 0x80000003 退出，没有窗口。因此真实界面和续聊验证未完成。

## 对产品设计的含义

- 不应再说“使用程序副本必然失去设置”。设置和记录可以做迁移。
- 不应直接把日常 profile 指给另一个同时运行的 Claude：单实例、自动恢复、计划任务、工作区绝对路径、浏览器数据库锁、Windows 注册行为都需验证。
- 在当前条件下能给出的结论是文件级迁移可行，真实 UI 与续用仍待验证。不能将本轮结果做成默认正式功能。
- 下一次完整验证应在已有 VM/Windows Sandbox 等隔离系统内进行，或由用户主动关闭并备份原应用后做单实例迁移。当前机器未提供可直接启动的 Windows Sandbox；本轮没有启用组件、重启机器或终止用户任务。

临时程序、含私人数据的快照和诊断文件完成核对后删除。开发检查脚本留在被 Git 忽略的 .handoff 内；没有将私人数据、会话内容、Cookie 或密钥提交项目。
