# 官方账号版布局与第三方 Gateway：本机调查

用户目标：保留第三方 API，同时加载官方账号版的整套布局、导航与图标。2026-10-28 调查对象为本机 Claude Desktop 4.29.0 macOS 安装；这是一份可行性结论，不是布局功能交付。

## 已观察到的边界

- 本机第三方窗口实际来源为 `app://localhost`，不是在线官方账号页面；中文插件只向此来源加载官方语言目录。
- 已安装主进程模块的第三方部署实现将主窗口地址返回为本地来源。它对非本地来源的主窗口导航设置拦截，对账号 API、OAuth 客户端和会话桥接也有独立分支。
- 本地 `ion-dist.asar` 通过自定义协议提供页面及部分 `/api/` 路由；未实现的账号相关路由有明确失败响应。推理 Gateway 的存在并不等于它实现了官方网页所需的账号、历史、项目等接口。
- 配置中确有 Chat/Code/Cowork 表面开关，但这些字段本身不能证明可把官方账号版网页替换进 Gateway；本轮没有更改这些配置或发送测试消息。

因此，不能把“增加官方中文”扩展为“更换全部官方账号版资源即可工作”。直接覆盖资源或替换导航目标，可能使页面跳转受阻、进入账号登录，或让界面请求不存在的后端接口。以上后果是根据静态调用和接口分支作出的推断，未对日常窗口实施破坏性实验。

## 当前交付边界

0.2.2 修复本机 macOS 自动中文、监听生命周期、打包与说明；不提供整套账号版布局替换。保持当前 Gateway、账号资料和会话路径。

如果继续做视觉适配，需要先取得目标版本的实际界面参考，再逐项映射到本地可用功能，验证导航、模型选择、历史和输入流程。纯外观适配与加载官方在线账号页面是两个实现方案；不能用外观相似宣称获得官方账号能力。

- 本机 GUI：第三方窗口实际来源、Code/Cowork 页面及正常退出再启动自动中文已观察。
- 普通只读 ASAR 检查：主进程模块 `.vite/build/index.chunk-C7NkbHFq.js`，模块 SHA-256 记录在本机忽略的调查目录；未修改应用包、签名、Gateway 或认证。
- REA 静态分析 Evidence：`ev_b2b6435981ffe78a5595999d08987f98fdf5141e97995758817726e3eaabbf5a`，对象为从同一安装提取的单个主进程模块。仅用于静态关系旁证；分析明确报告图覆盖不完整，不证明所有分支的运行行为。
- 全包 REA 分析遇到一个 unpacked 原生组件的声明完整性差异，后续全包扫描超时；本轮没有把该结果当作完整程序审计或篡改结论。缩小到目标 JS 模块后的静态分析成功。
