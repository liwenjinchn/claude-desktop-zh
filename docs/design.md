# 实现与恢复设计

调用顺序是 `catalog cache/import/fetch` → `plan` → `prepare-copy` → `launch`。脚本和 magpie 页面只处理用户输入；补丁、资源匹配和恢复由 CLI 模块统一负责。

## 选择独立副本

考虑了两种安装形态：原位修改和独立副本。原位修改更接近普通快捷方式，但商店目录权限、应用更新和回退会影响原安装。当前选择独立副本，并为数据和网关配置提供单独目录。该选择不代表 macOS 副本能保留官方签名。

不改 `app.asar`。只修改外部 `ion-dist` 的两个前端 JS，并为可用语言新增基础、动态 JSON。语言运行时注册、资源 URL 和语言名称选择器都必须找到唯一锚点。锚点改变时停止，不使用模糊的全局英文替换。

## 模块与状态

- `catalogs.mjs`：校验 JSON，保存内容寻址的资源快照，匹配基础和动态消息，检查占位符名称。占位符检查不是完整 ICU 语法验证。
- `cache.mjs`：只读取 `https://claude.ai/i18n/<zh>.json` 及动态资源；支持 block cache 和 Brotli、gzip。一个损坏条目不会阻止其他条目的导入。
- `patch.mjs`：只生成内存中的改动计划，不写应用。
- `install.mjs`：创建副本、隔离数据、备份、应用补丁、切换和恢复。
- CLI：参数校验、单写入锁、JSON 结果。不会输出网关密钥。

资源来源、导入时间、响应哈希和规范化 JSON 哈希分别保存。一个版本可有多个候选资源，选择本地匹配键最多的一份。中文缺失、占位符无法确认兼容的条目都回退英文。资源内容不作为 JavaScript 执行。

受管副本有 `3p-zh-state.json` 和 `.3p-zh-backup`。状态依次为 `applying`、`preparing`、`installed`、`restored`。切换语言从原始备份重建，受管文件同时记录原始、上一版和目标哈希，以便处理部分写入后中断。

所有恢复检查在第一次写入前完成。每个目标必须位于受管目录内，不能通过符号链接跳出目录。备份哈希或应用 ASAR 哈希不符时拒绝恢复。状态和文件使用临时文件重命名写入，CLI 同一副本只允许一个写入操作。

## 保持更新可解释

不通过修改 ACL、EXE fuse、ASAR 完整性、SIP、Gatekeeper 来扩大兼容范围。不提供常驻后台进程。应用更新后重新 `inspect` 并创建新副本。首版没有自动更新副本，也不向 magpie 注入不存在的网关生命周期 hook。
