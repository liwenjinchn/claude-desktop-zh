# 实现与恢复设计

## 入口和职责

magpie 设置页只保存默认语言。宿主工具、本机工作台和 PowerShell/sh 包装脚本均调用同一个 CLI；页面没有第二套补丁实现。插件默认 original 模式；copy 是显式测试选项。

CLI 的独立资源仓库默认为当前目录 `.catalogs`。插件显式传入 LocalAppData 下的仓库。显式参数优先，自动发现按命令需要执行，恢复不应依赖网关配置或语言缓存。

## 汉化需要修改什么

普通模式读取在线界面，所检查的 3p 版本读取本地 `app://localhost`。完整中文需要基础和动态官方语言资源，以及前端语言列表、加载入口、选择器名称注册。单独改 config.json 的 locale 或调用外壳语言接口不能补齐主界面。

`patch.mjs` 生成内存计划：两个外置 JS，加每种可用语言的基础和动态 JSON。不修改 EXE、app.asar。要求唯一锚点；未知结构或版本漂移停止。

`catalogs.mjs` 保存来源、导入时间和 SHA256，按与本地英文键集的匹配率挑选候选。基础覆盖率至少 95%；中文缺失或占位符无法确认兼容时回退英文。参数检查不是完整 ICU 语法验证。语言资源始终作为 JSON 数据处理。

## 原位模式

`original.mjs` 只管理原应用资源，备份放在应用外的状态目录。没有创建/迁移用户数据的逻辑，成功后使用原启动入口。它不保证未知版本的全部功能已通过实机测试。

默认备份：`%LOCALAPPDATA%/claude-desktop-3p-zh/original`。事务记录为 original-state.json，状态 preparing、applying、installed、restored。preparing 先于备份复制落盘，并记录前一事务；取消只清理新准备的备份，不写应用。切换利用备份原文重新构建，不叠加替换。应用目录锁防止不同备份目录同时写同一个程序，CLI 状态目录锁保护同一份状态。

写入要求目标进程停止、目录可写；检查 app.asar 和受管资源哈希。恢复在第一次资源写入前检查全部备份和目标。版本变化时拒绝旧备份覆盖新版；尚无自动跨版本迁移。

受保护 MSIX（WindowsApps 路径或附近存在 AppxManifest.xml）直接拒绝，不改 ACL，不接管所有权，不自动转副本。只读兼容性中的 eligible 是策略/结构检查，最终写权限仍需操作时确认。对本机商店版，没有验证出可用的外部资源覆盖入口。

## 副本模式

`install.mjs` 保留独立副本流程：prepare-copy → launch → 关闭副本 → switch/restore。prepare-copy 复制程序并创建新的部署与数据配置，仅带入必要网关参数；不会继承全部用户设置、登录态或会话。

副本使用 3p-zh-state.json 和 .3p-zh-backup，状态还包含 preparing。launch 传入 --user-data-dir 并为子进程指定 LOCALAPPDATA，直接双击 exe 不保证隔离。程序复制与用户数据隔离是两个设计选择；当前没有共用日常数据目录的选项。

## 工作台和运行边界

本机随机端口、fragment 会话令牌、精确 Host/Origin 检查。写操作需要明确确认，一次一个操作，保留有限任务历史。不在插件启动时自动写入；旧自动同步选项不启动轮询。宿主生命周期未全面实测，工作台以空闲超时回收，不假定宿主会调用 dispose。

CLI 超时或进程中断不是成功，应先检查事务状态。不会停止用户任务或更改快捷方式。macOS 仅 inspect/plan，不重签、不改变系统保护。测试与真实平台能力的区别见 [验证记录](validation.md)。
